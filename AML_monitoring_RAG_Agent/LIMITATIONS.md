# LIMITATIONS.md — Flaws, Assumptions, and Bounded Validity

This document outlines the unflattering technical limitations, assumptions, and bounded validity of this research prototype.

---

## 1. Synthetic Data & External Validity Bounds
- **IBM AMLSim Synthetic Baseline**: The transaction dataset used (`HI-Small_Trans.csv` / `dev_subset.csv`) consists entirely of synthetic transactions generated by IBM AMLSim software.
- **Generator-Defined Labels**: Ground-truth money laundering labels (`Is Laundering = 1`) are defined by pre-programmed rules inside the synthetic generator. Performance on synthetic data does not guarantee generalizability to real-world banking networks.

---

## 2. Model & Retrieval Scope
- **Single Embedding Encoder**: Dense vector search currently uses a single lightweight embedding model (`all-MiniLM-L6-v2`, 384 dimensions). It has not been benchmarked against domain-specific financial embeddings (e.g., FinBERT).
- **English Language Limitation**: The regulatory corpus and NLI entailment judge operate exclusively on English text.
- **No Live Sanctions Integration**: The sanctions screening module uses a static dated snapshot (`OFAC_SDN_SNAPSHOT`) and does not connect to live API feeds (e.g., Dow Jones, Refinitiv, OFAC live updates).

---

## 3. Evaluation & Annotation Bounds
- **Small Annotation Pool**: Benchmark queries and reference answers depend on a small initial candidate pool and require further human annotation iterations.
- **Judge Model Bias**: Automated entailment judging using cross-encoder NLI models carries inherent model bias and may occasionally misclassify complex legal phrasing.
- **Absence of User Study**: No formal human analyst user study was conducted to measure real-world investigation handling times. Claims regarding investigation speedup are hypothetical.
